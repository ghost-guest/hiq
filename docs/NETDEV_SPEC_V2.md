# Hiq 运维能力扩展规格说明书（NETDEV_SPEC v2）

> **版本**: v2.1 | **日期**: 2026-08-29 | **状态**: R1-R5 全部落地；2026-08-29 裁决——原 R6 批次改组为「按需停车场」（§八：启动条件触发立项，小件池无门槛），主线至此无欠账
> **前置**: NETDEV_SPEC v1.1（P0-P5 已全部落地）。本篇不推翻 v1 任何已落地行为，只做扩展；与 v1 的冲突点（非目标修订）统一收录于附录 A。
>
> **定位**: 把 netdev 从「网络设备诊断工作台」扩展为「全栈运维台」。三个扩展轴 + 一条界面契约：
> ① **数据面广度**——Docker / K8s / 数据库 / Web 服务器 / 安全设备 / GPU 主机成为一等公民；
> ② **高频动作 UI 化**——日志聚合、主机体检、人工终端、文件通道不再依赖对话式逐条执行；
> ③ **平台能力**——入站事件（trap/syslog）、时序指标、安全排查中心（ASM / 案例 / 证据包）；
> ④ **界面契约（§十）**——监督面板不增页签、任务进主区工作台（≤3 个）、一个动作一个家、能力感知渐进披露、六层引导与「选择题优先」表单契约（§10.9）：能力可以多，界面元素不随能力线性增长。

## 一、背景与动机

### 1.1 已有资产（v1.1 落地、v2 直接复用）

| 资产 | 位置 | 在 v2 中的角色 |
|---|---|---|
| 只读密封 + 提案流水线 + 审计 | `internal/netdev/{tools,proposal,audit}.go` | 一切新目标类型挂接的脊柱 |
| 日志源管道 file:/journal:/docker: | `internal/netdev/logsource.go` | Log Explorer 的地基（已完成约 80%，缺 UI 与编排） |
| 主机读命令白名单（ps/ss/last/…） | `internal/netdev/driver/hosts.go:56-78` | 主机体检的采集面 |
| 弱口令核查 | `internal/netdev/assess.go` + `NetDevWeakCredCheck` 桥 | 后端就绪，仅缺 UI |
| 拓扑双数据源 + 设备清单 + 配置基线 | topology / baseline / scanimport | ASM 层（CVE 匹配、暴露面、攻击路径）的原料 |
| 本地 sqlite 依赖 | modernc.org/sqlite | 时序面存储，零新增依赖 |
| B-E 批路线图 | NETDEV_SPEC v1.1 §10.5 | B 批→R5，C 批→R4，D 批→R3，E 批→保留 |

### 1.2 差距（2026-08-27 两轮评审结论摘要）

1. **目标类型**：Docker / K8s / 数据库 / 安全设备零原生接入（现仅 SSH 白名单代跑 docker/kubectl 只读命令）；go.mod 无 K8s/Docker SDK、无任何 SQL 驱动。
2. **日志**：管道有、界面无。无单机多源统一时间线、无跨设备 IOC 检索；设备表单的 `log_paths` 白名单配置后没有任何消费方。
3. **安全排查**：只能靠对话逐条跑命令；无主机基线 diff、无案例/时间线、无证据包；Finding 产生后没有任何主动出口。
4. **平台**：纯轮询纯拉取，无入站事件；无时序存储（一切指标是一次性文本）；30s 全量刷新与单层设备表不可规模化。

### 1.3 用户画像补充（v1 的老张/小李/王经理之外）

| 用户 | 画像 | 核心诉求 |
|---|---|---|
| 阿豪（全栈运维） | 管几十台 VM + K8s + 数据库 + 网络设备 | 登一台机器，单视图同时看 journal + docker + nginx + mysql 慢日志 |
| 蓝姐（安全响应） | 出事时 30 分钟出「入侵时间线 + 影响面 + IOC 清单」 | 一键主机体检、跨设备 IOC 搜索、可导出的证据包 |
| 飞哥（FDE） | 在客户机房干活，客户安全团队盯着每一步 | 环境快照、带审计的动作、离场诊断包 |
| 大伟（数据库研发） | 一半时间写内核/管几十个实例，另一半时间解释「为什么慢」 | 慢日志指纹聚合（TopSQL）、锁树与等待事件、复制拓扑与延迟、参数基线 diff、升级前后压测回归 |

v2 的五个决定成败的时刻：**第一次在单视图看完一台机器的全部日志**、**第一次一键主机体检出带证据的报告**、**第一次 trap 弹出 Finding 并推送到手机**、**第一次把证据包交给客户安全团队**、**第一次把全网慢 SQL 聚合成 Top10**。

### 1.4 设计不变量（延续 v1 §6.1，全部继续成立）

结构性只读 / 提案式写 / 范围白名单 / 全量审计 / 人工跳板注册 / 模式人切。**新增第七条：新数据面（日志 / 指标 / 事件 / K8s / DB / API）默认同样只读**——任何新接入方式必须先映射到分类器四类（read/write/dangerous/unknown），写能力只能以 §7.1 的结构化提案步骤类型存在。

## 二、目标模型扩展（target kinds）

### 2.1 kind 判别式

`[[netdev.devices]]` 增加 `kind` 字段作为数据面判别式；省略 `kind` 时按现有 `vendor` 推断（**向后兼容，存量配置零迁移**）。网络设备驱动（huawei/cisco/zte/vmware/redfish）行为不变。

| kind | 数据面 | 传输 | 只读能力映射 |
|---|---|---|---|
| linux / windows | CLI（现状） | SSH | hosts.go 读表 |
| **docker** | Docker Engine API | 本机 npipe/unix socket，或经 SSH 隧道到远端 socket | GET 白名单（§2.2） |
| **k8s** | Kubernetes API | kubeconfig（https） | get/list/logs/events（§2.3） |
| **db** | MySQL / PostgreSQL / Redis 协议 | TCP（可经跳板链） | 只读会话语义（§2.4） |
| **web** | Linux 主机 + Web 服务器 profile | SSH | 预设命令与日志路径（§2.5） |
| **firewall** | 厂商 REST API | https | 只读端点白名单（§2.6） |
| **gpu-host**（§8.4 停车场） | DCGM/NVML | SSH 到 GPU 节点 | §8.4 |

### 2.2 kind=docker

- 客户端：`github.com/docker/docker/client`，仅构造 GET 路径调用；POST/DELETE **无客户端代码路径**（结构性只读在库选型层面保证）。
- 白名单端点：`/containers/json`、`/containers/{id}/json`、`/containers/{id}/logs?tail=N`、`/containers/{id}/stats?one-shot`、`/images/json`、`/info`、`/version`、`/events`（时间盒 ≤60s）。
- 连接方式三选一：本机 Windows named pipe（管理本地 Docker Desktop）／远端 `ssh://` 内置隧道（docker client 原生支持）／`tcp://` 直连（须清单内地址）。
- 与现有 `docker logs --tail` 白名单（hosts.go）并存过渡：目标注册为 kind=docker 后优先走 API。

### 2.3 kind=k8s

- 客户端：`k8s.io/client-go`，仅使用只读 verb（get/list/watch-时间盒）；`apply/scale/delete` 无诊断手路径，写走提案步骤 `k8s-apply`（§7.1）。
- 凭证：kubeconfig **路径或内容入 secret store**，agent 工具层只接受 target 名——不接受 kubeconfig 内容、context 名、server URL 任何参数（防 SSRF 与 context 切换逃逸，附录 B-7）。
- 能力：`get/describe`（pods/deploy/svc/ingress/node/events）、`logs --tail/--since`（容器选择经 namespace/workload 浏览，不要求用户手拼 pod 名）、`top`。
- 多集群：一个 target = 一个 kubeconfig + context；集群间无共享状态。

### 2.4 kind=db

- 驱动：`go-sql-driver/mysql`、`jackc/pgx`、`redis/go-redis`；仅拨清单内地址，可走跳板链（TCP 经 SSH direct-tcpip，复用现有 dial 链）。
- **默认读集**（结构性白名单，非 SQL 文本分类）：
  - MySQL：`SHOW [FULL] PROCESSLIST`、`SHOW GLOBAL STATUS`、`SHOW GLOBAL VARIABLES`、`SHOW ENGINE INNODB STATUS`、`EXPLAIN`、慢日志经 `file:` 源读取、`SELECT` **不在默认档**（附录 B-1）。
  - PostgreSQL：`pg_stat_activity`、`pg_stat_database`、`pg_locks`、`EXPLAIN`、日志经 `file:`。
  - Redis：`INFO [section]`、`SLOWLOG GET n`、`CLIENT LIST`、`MEMORY STATS`、`LATENCY HISTORY`。
- 每次会话有查询条数与时长预算（沿用 turn 预算机制）；审计记录语句全文与行数。
- **系统视图特例**：`performance_schema` / `sys` / `information_schema`（MySQL）、`pg_stat_*` / `pg_catalog`（PG）属**只读元数据视图，纳入默认读集**——它们是诊断面板不是用户数据；用户表 SELECT 仍按附录 B-1 管控。研发深度能力见 §2.8。

### 2.5 kind=web

不新增驱动——是 linux kind 之上的 **profile 预设包**：内置 nginx（`nginx -T` 只读、stub_status、access/error 日志路径预设）、apache（`apachectl -M/-S`、server-status）、tomcat/openresty 同理。`nginx -T` 输出过脱敏器（证书块指纹化）。预设以 v1「知识库生长」机制维护（RAG 命名空间 + 读表扩展）。

### 2.6 kind=firewall（安全设备）

以厂商 REST API 为数据面（非 CLI），首批二选一：fortinet（`/api/v2/monitor/*` 只读端点：系统状态、会话表、接口流量；`/api/v2/cmdb/*` 仅 GET）或 paloalto（`type=show/op=<白名单命令>` + key 认证）。端点白名单进驱动表，unknown 端点默认拒绝（沿用 v1 附录 B-1 精神）。后续按需扩 H3C / 山石 / 华为 USG（USG 可先走现有 huawei-vrp CLI 驱动）。

### 2.8 数据库研发深度面（kind=db 的工程视图，面向 DB 研发/DBA）

- **TopSQL 慢日志指纹聚合**：慢日志按查询指纹（归一化 SQL）聚合出 TopN（次数/总耗时/P95）——日志工作台 db 源的「聚合」视图，复用 logsource 拉取 + 本地指纹化（类 pt-query-digest），实例侧零安装；
- **锁树与等待事件**：MySQL `data_locks`/`sys.innodb_lock_waits`、PG `pg_locks` + blocking 链 → 锁树渲染（谁阻塞谁、等了多久）；wait events 聚合入时序面；
- **复制拓扑与延迟**：复制关系自动发现（`SHOW REPLICA STATUS` / `pg_stat_replication`）→ 拓扑图（复用拓扑组件：节点=实例、边=复制+延迟标注）；延迟入时序面；
- **参数基线与调优**：参数快照 vs 内置推荐基线 diff（同网络配置基线思路）；参数变更走提案（file-upload 步骤 + 重启标记 dangerous）；
- **容量与水位**：表空间/增长趋势入时序面；PG 膨胀检测；
- **DDL 锁风险评估**：sql-migration 提案生成时附锁风险评估（是否锁表、建议 gh-ost/pt-osc 在线变更路径的提示——产品只评估不代替执行）；
- **压测回归**：sysbench/tpcc 作为「诊断组合」preset 仅对 staging 组目标开放；生产组归 dangerous；
- **EXPLAIN ANALYZE 归类**：它会真实执行查询，**默认归 write**（转提案/评估信封内）；普通 EXPLAIN 保持 read。

- **迁移演练（migration rehearsal）**：一键编排 = restore-verify（§7.3）恢复生产快照到 staging → 执行 sql-migration → 计时 + 锁监控（复用锁树数据源）→ 出报告（耗时/锁峰值/失败即弃）——大表 DDL 上线前「会不会锁死业务」不再靠嘴答；仅 staging 目标可作接收方。

分期：TopSQL / 锁树 / 复制拓扑随 R2 db kind 落地；参数基线、DDL 评估、压测回归、迁移演练入 §八停车场（按需立项）。

## 三、日志面（Log Explorer）

### 3.1 日志源扩展（logsource.go 增量）

现有 `file:` / `journal:` / `docker:` 之上新增：

- `k8s:<namespace>/<workload>`：经 kind=k8s target 解析为 pods → `logs --since --tail`；
- `db:<target>`：kind=db 目标的慢日志/错误日志（引擎预设路径或 `file:` 组合）；
- `web:<target>`：kind=web profile 的 access/error 预设路径；
- `winevt:<channel>`：Windows 事件日志（`Get-WinEvent` 过滤语法白名单），安全通道预设高频事件 ID（4624/4625/4688…）——`Get-WinEvent`/`wevtutil` **新入 Windows 读表**，Windows 排查的刚需；
- `event:<设备>`：R3 接收器落地后，网络设备/主机发来的 syslog 本地入库流——交换机 logbuffer 与主机日志同屏（§5.1 联动）；
- 时间戳解析器格式清单：syslog / ISO8601 / nginx CLF / apache / mysql slow log / `[dd/mm/yyyy hh:mm:ss]`；时间戳按设备本地时区标注，跨源合并时结合体检采集的 NTP 偏移给警告（§4.1/§10.3）；
- 保持现有约束：tail 默认 100 / 上限 1000 / 拉取上限 2000，`since` 与 `grep` 客户端过滤，路径白名单沿用 `log_paths`（`/var/log` 默认放行）。

### 3.2 单机聚合时间线（主区「日志工作台」，布局契约见 §10.3）

- 左栏：目标选择器（设备 → 源列表：journal 单元 / docker 容器 / k8s workload / 白名单目录 / db / winevt 预设，多选；R5 起另有「变更 / 事件 / Finding」三类关联源，§5.4）；
- 主区：**统一时间线合并视图**（复用 `extractLogTimestamp` 的解析器，无时间戳行吸附到前一条），虚拟滚动；
- 过滤栏：关键字/正则高亮、级别着色（仅 ERROR/WARN 两档）、时间窗缩放；
- 每行可溯源：跳转原始命令与审计条目；
- 底栏：跨设备搜索的固定能力位（§3.3 结果就地展开）；
- 深链 `?bench=logs`（§10.2）。

### 3.3 跨设备 fan-out 搜索（新工具 `netdev_log_search`）

- 入参：pattern（正则）、目标集（设备组/project/全部）、时间窗、源类型可选；
- 语义：对每个目标并行执行 §3.1 的拉取+过滤（并发默认 8，逐设备 tail 沿用上界，整轮受命令预算约束——预算不足时明确报告覆盖了多少台）；
- 输出：命中表（设备 / 源 / 时刻 / 命中行 ± 上下文 2 行），一键「转入 IOC 台账」（§4.3）或「按此设备过滤进时间线」。
- 这是入侵排查「拿一个 IP 搜全网」的主入口。

### 3.4 边界

日志面保持**拉取式、有界返回**：无常驻采集、无落盘流式存储（趋势化需求由时序面 §5.3 承担，不混入日志）。

## 四、安全排查中心

### 4.1 主机体检（新工具 `netdev_triage`，R1 v1 版）

单目标一键电池，产出结构化 TriageReport（进 Finding 体系，证据链逐条可溯）：

| 采集组 | 命令（hosts.go 读表内/新增） | 输出结构 |
|---|---|---|
| 进程 | `ps auxww` / `tasklist /v` | 异常项标注：无路径/无父/隐藏/高 CPU |
| 网络连接 | `ss -tulnp` / `netstat -ano` | 监听端口表 + 外连表（按远端 IP 聚合） |
| 登录 | `last -F n50`、`lastb n50`、`who`、`w` / `quser` | 最近登录 + 失败统计（爆破源 IP TopN） |
| 持久化 | `crontab -l`（**新入读表**）、`systemctl list-unit-files --state=enabled`、`ls -la ~/.ssh/authorized_keys`（输出脱敏为指纹） | 持久化点清单 |
| 账户 | `/etc/passwd` 解析（uid=0、可登录 shell、近期 mtime） | 账户异表 |
| 资源 | `df -h`、内存/负载 | 水位告警 |
| 时钟 | `timedatectl` / `ntpq -p` / `w32tm /query /status` | NTP 偏移量——跨源日志合并可信度的前提，超阈值联动时间线警告（§10.3） |

v1 为顺序执行（复用 inspect.go 模式）；R4 的 Job 引擎（v1 C 批）落地后升级为带 expect/timeout/断点的 runbook。

### 4.2 主机基线快照与 diff（R5）

- 巡检/体检结果抽取**可比集合**：账户名集、监听端口集、crontab 条目集、enabled unit 集、外连 IP 集，存 sqlite 快照；
- 两次快照差集 = Finding（「7 天内新增可登录账户 1、新增监听端口 3」），差集项一键跳最新证据；
- 快照保留期默认 90d，可按设备组关闭（隐私开关）。
- 快照的可比集合天然支撑**定时任务治理**：全集群 crontab/enabled-unit 的日历视图（重复、失败、孤儿任务标注）——R5 附带交付。

### 4.3 IOC 台账与富化（R5）

- 案例内维护 IOC 列表（IP/域名/文件哈希/关键字），来源：手工、log_search 命中转入、外部 feed 导入（feed 用户自备，同附录 B-4 原则）；
- 富化动作 = 对台账批量触发 `netdev_log_search` + 体检外连表比对。

### 4.4 弱口令核查 UI 接线（R1，纯前端）

后端 `NetDevWeakCredCheck` 已就绪：设备组右键 →「弱口令核查（默认档）」，结果进 Finding；高级档（用户自备字典）入口同一处，先读锁定策略建模（assess.go 既有逻辑）。

### 4.5 ASM 层（R5）

- **清单 × CVE 匹配**：设备 vendor/os/model/版本字段 × 本地 CVE feed（导入器支持 NVD JSON 导出，产品不分发 feed）→「这台 IOS 有哪批已知漏洞」；匹配结果挂设备卡，进巡检报告。
- **暴露面视图**：清单外资产（scanimport 已有）+ 证书到期（openssl s_client 读白名单）+ 弱 TLS/管理面端口（发现扫描已有端口数据）合成一页「该收敛什么」。
- **攻击路径图（阶段二）**：拓扑图 + ACL/分段规则（从防火墙 target 读）+ 跳板可达性 →「从 X 到 Y 的可行路径」。v2 先做数据结构与单源路径展示，图算法迭代后置。

界面落点：安全工作台「暴露面与 CVE」页签（§10.4）；设备卡以 CVE 计数徽标链接进入。

### 4.6 案例与时间线（R5）

- Case = { 标题、状态、IOC 台账、时间线条目（引用 Finding/日志段/审计条目/人工笔记） }，本地 sqlite；
- 时间线构建器：左侧候选流（期间全部 Finding 与 log_search 命中），右侧钉到轴；
- 导出：Markdown/PDF 复盘报告。

界面落点：安全工作台（§10.4）——案例列表与 IOC 台账在左栏，时间线/暴露面为主区页签；Finding 卡提供「建案例」链接入口。

### 4.7 诊断包导出与审计哈希链（R5，吸收 v1 B 批）

- **诊断包**：勾选设备与时间窗 → 自动收集日志段（脱敏后）、配置/版本、体检报告、审计片段 → zip + 逐文件 SHA-256 manifest。FDE 离场件与蓝队证据件是同一功能。
- **审计哈希链**：`audit.jsonl` 每条附 prev-hash，启动校验，损坏点告警 Finding（v1 B 批原案）。

### 4.8 FDE 交付件（R5）

- **环境快照与验收报告**：prereq 电池（内核参数/端口占用/证书/磁盘布局/依赖版本，读表命令）→ 结构化快照 → 与要求基线 diff → 可签字验收报告（巡检框架复用，规则集换成软件前置条件）；
- **客户合规导出**：审计记录 + 提案 diff + 回滚凭证一键导出 PDF——「我们在你环境里做了什么」的自证文件；
- **离线部署完整性**：部署包 SHA-256 manifest 校验（与诊断包同一清单机制）；
- **权限预检**：prereq 电池新增受限账户能力探测（可执行命令集 / 缺哪些权限 / sudo 可用性——全部只读探测），部署前生成「就绪 / 受阻」清单；
- **离线升级兼容矩阵**：客户侧已装版本与依赖清单 vs 升级包要求 → 差异报告（缺什么、与什么冲突）。

### 4.9 流量面与 Canary（Canary 随 R5，流量面入 §八停车场）

- **有界抓包**：远端 `tcpdump -c N` / `-G 秒` 有界采集（入读表 + 预算 + 落盘上限）→ SFTP 下载通道 → 本地五元组聚合视图；不做常驻镜像口；
- **流量元数据摄取**：客户已有 Zeek/NetFlow 输出时，`file:` 源直接摄取进日志工作台（零新增采集面）；
- **Canary/蜜罐标记**：假账户、假共享、假配置文件经**提案**部署（结构化、留痕、可回滚），canary 被触碰产生最高级 Finding——检测体系里最便宜的传感器。

### 4.10 Finding 生命周期与告警工作队列（R3 基础态，R5 完整）

Finding 从「一次性结论」升级为工作对象：

- 状态机：`open → acknowledged → resolved / false-positive`；`escalated` = 转入案例（§4.6）；
- **同类聚合**：同规则/同根因键的 Finding 合并展示（「接口 down ×17」为一条队列项，展开 17 台）；
- **工作队列 UI** =「发现」dock 页签升级：按严重度 × 资产价值排序，批量 ack/resolve，处置备注与处置人入审计；
- **误报学习**：false-positive 标记反馈给事件规则（§5.1）与体检规则——同类再触发自动降级，并附「此前被标记误报 N 次」。

### 4.11 定位与路径取证（R3）

- **`netdev_locate`（IP/用户定位）**：输入 IP / MAC / 用户名 → 并发查清单内设备的 ARP 表 / MAC 表 / DHCP lease（全在只读白名单内）→ 输出接入设备、端口与最后 seen 时间。网工「这个 IP 接在哪」与蓝队「可疑 IP 的物理位置」共用一个工具；只查清单内设备；
- **路径时序基线**：周期性 traceroute（跳数有界、仅清单内目标）逐跳时延入时序面——「网慢但无告警」时对比本周与上周逐跳时延，劣化跳一眼可见。

## 五、事件面与时序面（吸收 v1 D 批）

### 5.1 本机事件接收器

- **Syslog**（UDP 514 / TCP，RFC3164+RFC5424）与 **SNMP Trap**（UDP 162，v2c）；
- 仅应用运行时监听，**不装后台服务**（与「设备侧零安装」对称；7×24 需求由停车场 §8.1 分域探针承接，附录 B-3）；
- 源 ACL：只接受清单内设备 IP，其余丢弃计数；
- 事件 → 规则（内置：链路 down/up、登录失败突增、设备冷启动）→ Finding；**防洪水**：同源同 OID 5 分钟窗口聚合 + 全局限速 + 熔断（附录 B-11）；
- Trap 团体字作为设备凭证之一入 secret store，脱敏规则覆盖。

### 5.2 通知出口

- Finding（可分级订阅）→ webhook 通用 + 飞书/钉钉/企微模板 + SMTP；
- 内容过脱敏器；出口配置在设置页，测试发送按钮；
- **深链回桌面**：通知携带 `hiq://finding/<id>` / `hiq://case/<id>` 深链，点击直达对应队列项——值班从手机回到工位的最后一厘米；
- **升级链**（R5，联动 §4.10 ack 状态）：critical Finding 超时未 ack → 自动通知升级序列中的下一人；
- 这是「检测没有出口等于没有检测」的补丁，也是值班场景的入口。

### 5.3 时序面

- 存储：现有 sqlite，表 `series(target, metric, labels_json, ts, value)`，按天分区滚动、默认保留 14d；
- 采集器（定时巡检调度器扩展，复用 inspection_interval 机制）：SNMP 接口计数器（已有）→ 速率换算；kind=docker → 容器 CPU/内存；kind=k8s → node/pod top；linux → `/proc` 快照（读表内）；firewall → 会话数/吞吐；
- UI：设备卡**迷你趋势图**（sparkline，24h），context 页签大图；无 Grafana 集成野心——先服务「看日志前看一眼曲线」。

### 5.4 时间关联层（R5；数据源 = v1 审计 + R3 事件/时序 + Finding）

回答两个最高频的运维问题：「**最近谁改了什么**」与「**这台机器/这段时间发生了什么**」：

- **变更-故障关联时间轴**：以设备/服务/案例为轴，把变更（提案执行、审计写操作）、事件（trap/syslog）、Finding、指标异常点并排渲染在同一条可缩放时间轴上；设备卡趋势图上直接标注变更标记点，相关性由人眼判断——一半的故障是变更引起的，让这个直觉第一眼可见；
- **实体 360°**：选定设备 + 时间窗 → 自动勾齐该实体的全部源（日志/变更/事件/Finding/审计），在**日志工作台**内呈现——日志工作台本来就是多源合并时间线，本层只是给它增加「变更/事件/Finding」三类源类型与一键预设，**不新增任何界面面**（守 §10.1/§10.2 契约）；
- **期望状态对比**：清单/巡检声明的期望态（应有 N 台在线、某服务应 running）vs 实时采集 → 缺失与多余清单（「掉电恢复后缺的 13 台是谁」）。

### 5.5 报告族（DailyBriefing 扩展，R3 起）

从「日报」扩展为多粒度报告，全部一键导出（MD/PDF）：

- **值班交接报告**：夜间事件 + 本人处理动作（来自审计）+ 未闭环 Finding；
- **周报/月报**：变更 N 起（按组/按人）、故障与 Top 问题、基线 diff 摘要；
- **慢 SQL 周报**：本周新增/恶化/改善的查询指纹（§2.8 TopSQL 的 diff 化）；
- **凭证健康盘点**：凭证清单 × 最后使用时间 × 轮换建议 × 孤儿凭证（无引用的 secret 标记待删）；
- **资产报表**（R5）：分组统计、OS/版本分布、生命周期状态导出；
- 全部报告导出**一律过脱敏器**（与诊断包同一套规则）——复盘报告里的内网地址与密钥指纹受同一策略管控。

### 5.6 自身数据管理（R3 基础，R5 迁移向导）

spec 其余部分管理客户的设备；本节管理产品自己的数据——用户用满三个月后必然撞上：

- **导出/导入（换机与重装）**：一键打包 netdev 状态目录（findings、案例、备份库、体检快照、时序、审计）+ secret store（`secrets.enc.json` 以用户口令重新加密导出，TOML 清单随附）；导入端校验完整性（SHA-256 manifest，与诊断包同机制）；
- **容量治理**：统一保留策略——审计（v1 `audit_retention`）、findings（默认 180d）、案例（永久，除非手动归档）、配置备份（每组上限滚动）、时序（14d）、体检快照（90d）；超限清理带 dry-run 预览；
- **升级兼容**：产品自身升级时的数据结构迁移（schema version + 自动迁移 + 失败回滚到升级前副本）。

## 六、人工通道（人可以，agent 不可以，全部留痕）

v1 哲学「GUI 人类专属」的正面表述：机器只读，人可交互，但人的动作同样进审计。

### 6.1 人工终端（R4）

- 设备卡「打开终端」：Go 侧 SSH PTY 会话直达设备（走同一 transport/跳板链/凭证），前端 xterm.js（复用 TerminalSession 组件）；
- 与 agent 会话**共享 VTY 预算**（`max_sessions_per_device`）；
- 全程录制：输入回显 + 输出（脱敏后）落 evidence，审计记录会话起止与字节量；回放复用 B 批审计回放视图；
- 紧急停止同样杀人工终端。

### 6.2 文件通道（R4）

- **下载先行**：SFTP 只读子集（list/stat/get），无 put/rm/mkdir 客户端路径；大小上限（默认 200MB）+ 落盘位置用户选择 + 审计；
- **上传仅存在于提案**：`file-upload` 步骤类型（§7.1），流程 = 备份目标现文件 → 上传 → 校验和验证；
- transport.go「no SFTP」注释随之修订为「SFTP read-only subset; writes only via proposal steps」。

### 6.3 带外启动器（R4，轻量）

设备卡「带外控制台」：ESXi/堡垒 Web UI 深链、`mstsc /v:`、BMC Web 入口——只启动本地工具与浏览器，产品内不实现 RDP/VNC 协议；点击入审计。

### 6.4 Telnet 裁决（R4）

v1 §3.3 规划的 Telnet 至今未实现（`allow_telnet` 字段无读取方）。二选一：按 v1 §3.3 实现（opt-in + 明文警告），或删除字段与 UI 开关。默认建议：**删**（现代环境 telnet 管理面应被收敛而非被工具纵容；确需带外走 Serial/带外启动器）。

## 七、提案系统扩展

### 7.1 结构化步骤类型

提案步骤从「CLI 命令字符串」扩展为判别联合：

| 类型 | 载荷 | 回滚依据 |
|---|---|---|
| `cli`（现状） | 命令 + 设备 | 配置备份（现状） |
| `k8s-apply` | yaml 全文 + target | apply 前的 live 对象备份（resourceVersion 钉住） |
| `sql-migration` | 迁移脚本 + target | down 脚本必填，缺则该步骤不可提交 |
| `file-upload` | 本地路径 + 目标路径 | 目标现文件备份 |
| `cert-replace` | 证书对 + 目标路径 + 服务 reload 命令 | 旧证书备份 + reload 可回退声明 |

全部类型继承现有状态机（draft→approved→executing→done/partial/failed）、首败冻结、组策略与变更窗口；`delete`/`scale down` 类动词落 dangerous + confirm2。模板变量只允许白名单字符集（附录 B-10）。

**执行前置检查**：每份提案开始执行前，自动对全部目标设备跑 `who` / `quser`（读表内）——发现**其他在线人员**则暂停并列出会话，人确认后才继续。「我要变更，但同事正登着这台设备」是最常见的协作事故，一行只读命令挡住它。

**执行后观察期**：状态机扩展 `done → watching（默认 30 分钟，组级可配，可关）→ closed`。观察期内持续对比变更目标的健康信号（接口错误 / 服务健康 / 慢查询计数等，来自时序面）与变更前基线，劣化超阈值 → 最高级 Finding + 附「一键发起回滚提案」（回滚仍需人批准——AI 的手永远慢一步）。

### 7.2 批量模板（R4）

- 模板 = 步骤序列 + 变量（按设备属性渲染：接口名、网段、hostname）；
- 生成时**逐台 dry-run diff 全量预览**，人审的是「N 份渲染结果」整体；
- 执行沿用滚动语义；回滚矩阵视图（每台一行：已执行/已回滚/未触达）。

**割接模式（cutover，模板之上的执行形态）**：整份 runbook 以带**总倒计时**的方式逐步执行——每步含预计耗时与**语义验证门**（如「OSPF 邻居 Full 且持续 60s」），门不过即停在预设**回退决策点**（回退按钮 + 影响描述并列，决策是人按的）；割接前后自动各拍一次全网基线快照，事后出对比报告（哪些接口/路由/流量变了）。把「Word 文档 + 对讲机」的深夜割接变成可执行、可回退、可复盘的流程。

### 7.3 服务器配置文件管理（R4）

对 linux 目标：白名单路径（`/etc/nginx/**` 等，沿用 log_paths 同款授权模式）→ 抓取快照入备份库 → 两版本 UnifiedDiff（复用网络配置 diff 组件）→ 修改走 `cli`（cp 备份 + sed 不允许——**编辑产物以 file-upload 步骤提交**，保持「人对整份内容签字」语义）。

- **环境 Drift**：同名配置路径跨 dev/staging/prod 目标（按 project 分组）的 diff 视图——同一份 nginx 配置三个环境差在哪；
- **备份恢复演练**：`restore-verify` 提案步骤类型——把配置/DB/文件备份恢复到指定 staging 目标并跑验证读，证明「备份真的能恢复」；生产目标不允许作为演练接收方。

## 八、按需停车场（原「R6 批次」——2026-08-29 裁决改组）

> **本章不是路线图**。R1-R5 落地后 netdev 主线已完成；下列条目只在「启动条件」被真实环境触发时立项，立项时按当期证据重定范围——不按菜单全做。每条附**最小可用面**：真启动时先交付的一小块，其余按实际使用证据再加。R1-R5 的全部界面契约（§十）与安全不变量对本章同样生效。

### 8.1 规模化

**启动条件**：单实例纳管 >200 设备，或轮询周期被迫拉长 >2 分钟（附录 B-12）。
分域（region/site 域 + 域内轮询组）、增量刷新（状态 diff 推送替代 30s 全量）、设备表虚拟滚动与分组导航。
最小可用面：域分组 + 分域轮询（增量刷新随后）。（批量导入已摘入 §8.7 小件池。）

### 8.2 gNMI 流式遥测

**启动条件**：环境内主流设备实际支持 gNMI（国产 VRP/ZXR10 支持面参差，先证实），且 SNMP 轮询压力成为实测瓶颈。依赖 8.1 的负载模型先行。
ON_CHANGE/SAMPLE 订阅 → 时序面，SNMP 轮询的接棒者。
最小可用面：单台设备 SAMPLE 订阅与 SNMP 轮询并行跑一周，时序面对比一致后谈接棒。

### 8.3 sFlow / NetFlow

**启动条件**：出现运营商/骨干网场景的真实使用者。
流量面：接收 → 五元组聚合（TopN 会话/接口利用率）→ 时序面 + Finding（异常外联突增），与安全排查的「外连表」互补。
最小可用面：sFlow v5 接收 + TopN 会话聚合表。

### 8.4 GPU 数据面

**启动条件**：公司自身 GPU 集群 dogfooding 产出真实痛点清单——按痛点重定范围，以下原菜单仅作素材库，不是承诺清单：
采集（DCGM/NVML：XID/ECC/NVLink/MIG + XID 知识库进 RAG）、Fabric 体检（`ibstat`/`nccl-tests` preset）、训练日志按 step 对齐、Checkpoint 治理（保留策略/完整性/跨节点取回，复用 SFTP 通道）、推理服务面（vLLM/Triton 指标）、节点横向对比（rank 速度/温度/ECC）。
最小可用面：DCGM XID 错误 → Finding（dogfooding 最常见的第一诉求）。

### 8.5 路由面与光层（运营商向）

**启动条件**：ISP 场景或自有骨干网的真实运维需求。
BGP 视图（`display bgp` 系列已在驱动读表、peer/前缀数入时序、RPKI/ROA 校验、MOAS 告警）与光层 DOM（收/发光功率/模块温度 → 劣化趋势告警）——复用现有数据面，无新协议栈。
最小可用面：BGP peer 状态入时序 + 中断 Finding。

### 8.6 （已摘出——原「拓扑人工覆盖层」移入 §8.7 小件池）

### 8.7 小件池（无门槛，按需随时可做）

- **拓扑人工覆盖层**（原 §8.6）：自动布局出错是第一天的事，与规模无关——**只叠加不篡改**：确认/删除未证实链路、节点位置微调、文字标注；覆盖层本地持久化、与自动数据分存，自动重算永不覆盖人工修正，冲突时标记提示人工裁决。
- **CSV/Excel 批量导入**（原 §8.1 摘出）：首次批量上架 20 台设备时就疼——导入进待确认区，人工核对后转正；不设规模门槛。

## 十、界面与信息架构（防乱与引导）

> 本章是 v2 全部新功能的唯一界面契约：**能力可以多，界面元素不随能力线性增长**。R1-R5 任何新入口若本章未给出落点，视为 spec 缺口，不得实现。现状基线：右栏 dock 七页签（实况/设备/手册/拓扑/发现/提案/审计，浏览器式可开可关）、主区 = 对话 + 终端面板、左栏底部四导航（设备清单/立即巡检/审计/运维偏好）——**这四导航与七页签在 v2 全程保持数量不变**。

### 10.1 五条组织原则

1. **监督在 dock，任务在主区。** dock 页签是"随时瞟一眼"的监督面板，页签**目录恒为 11**（v1.1 的七个 + 日志/健康/任务 + **浏览器**——2026-08-29 修订：浏览器控制台经评审裁决纳入，上下文驱动非默认开启、复用产物轴骨架，详见 pane-system-spec §8），**到此为止不再增长**；日志/健康页签定位是单设备快速尾随的监督视图。新能力中属于"状态与结论"的（体检报告、基线 diff、CVE 命中）一律以 Finding 形态进「发现」页签；属于"任务过程、需要横向空间与时间轴"的（多源合并日志时间线、案例时间线）仍是**主区工作台**。新能力中属于"状态与结论"的（体检报告、基线 diff、CVE 命中）一律以 Finding 形态进「发现」页签；属于"任务过程、需要横向空间与时间轴"的（日志时间线、案例时间线）成为**主区工作台**。
2. **工作台数量不变量 ≤ 3。** 主区 = 对话（默认）+ 日志工作台 + 安全工作台。对话永远是默认视图与返回锚点；未来新任务面必须并入现有工作台（作为页签或视图），不得增设第四个工作台。
3. **一个动作一个家。** 每个功能有且只有一个"家"（执行与管理它的地方）；其他位置只放**链接型入口**（跳转到家，不就地展开第二套 UI）。映射表见 §10.6。
4. **能力感知的渐进披露。** 工作台与设备卡只出现**已配置能力**的入口（未注册 kind=k8s 目标则 k8s 源选择器不出现；未配置 log_paths 的设备在源列表只显示 journal/docker 免配置项并附一句说明）。设置页与设备清单**永远**展示全部能力与注册入口——可发现性由"去配置"路径承担，而不是由工作台里的常驻灰按钮承担。
5. **徽标代替常驻。** 新信息默认以计数徽标/色点进入既有元素（dock 页签角标、设备分组行右侧计数），不新增常驻横幅。徽标规则见 §10.8。

### 10.2 主区工作台框架

- **切换条**：主区顶部 ≤32px 细条，内容为 chips（`[对话] [日志] [安全告警] [大屏]`）+ 右侧 `Esc 返回对话` 提示。**仅在非对话工作台为当前视图时渲染**——回到对话（Esc 或「对话」chip）即隐去，对话主区无论此前开过什么都与 v1.1 像素等价，零新增视觉成本；工作台首次打开后保持挂载（无 × 关闭、状态不丢），重进入口见下。
- 打开途径只有三种：上下文入口（设备卡「日志」、Finding 卡「建案例」、log_search 结果表）、命令面板、深链。
- 每个工作台状态独立保持（源选择、过滤、当前案例），关闭重开不丢；Esc 返回对话。
- 终端面板（主区底部）与工作台平级共存；人工终端会话是其中的设备页签（§10.5）。
- 深链：`?bench=logs&target=app-vm-01` / `?bench=sec&case=3`，沿用 `?dock=` 的调试文化。

### 10.7 引导体系（六层，从静到动）

1. **空态即教程**：每个新表面的空态 = 一句话 + 一个主 CTA + 一个"去配置"次链接。日志工作台无源时：「journal 与 docker 日志无需配置，勾选即用；自定义路径在设备编辑的 log_paths 添加 [去设置]」。安全工作台无案例时：三张出生卡（空白案例 / 入侵排查向导 / 先看暴露面）。清单某 kind 组为空时不显示该组（渐进披露），但设置页与「+ 注册目标」处始终列出全部 kind。
2. **场景向导（主动任务的唯一形态）**：入侵排查向导 = 五步 checklist 卡——① 圈定范围（选设备组）→ ② 并行主机体检 → ③ 输入 IOC/关键字全网日志搜索 → ④ 命中钉入案例时间线 → ⑤ 导出证据包/复盘报告。每步一个按钮驱动底层工具，进度就地显示，可中断续跑（依赖 R4 Job 引擎）。入口：安全工作台空态、命令面板、GettingStarted 第三步、DailyBriefing 异常摘要。**不为此新增任何常驻导航项**。
3. **GettingStarted 能力感知**：三步引导保留（设备 → 会话 → 首个 Finding），文案随已配置能力变化；注册首个 docker/k8s 目标后第三步追加「在日志工作台看它的容器日志」。
4. **DailyBriefing 主动 CTA**：晨报新增区块——昨夜事件摘要（R3）、基线 diff 摘要（R5）、证书到期/新增 CVE（R5），每条带跳转；未配置通知出口时首条显示配置引导（R3）。
5. **命令面板收录**：全部新入口（工作台/向导/体检/弱口令/导出）进命令面板，与 `?bench=` 深链共用同一注册表，作为键盘用户的统一发现层。
6. **设置内引导**：L2 每个分组行显示配置状态徽标（未配置 / 已配置 n 项 / 推荐未启用）+ 一句话价值说明；L3 面板头部固定「这是做什么的」一行与相关文档链接；版本升级带来的新能力在设置与命令面板标「新」徽标，直至用户查看；空配置组的主 CTA 直达最小配置流（如「从 ~/.ssh/config 导入第一台设备」）。

### 10.8 信息密度与默认值

- dock 页签角标：audit 未读数、proposals 待审数、findings 新增严重度色点（红 = critical/high）；>99 显示 `99+`；
- 隐藏规则：设备分组无异常不显示数字；对话视图下切换条不渲染（工作台保持挂载但隐于对话）；时间线级别着色仅 ERROR/WARN；
- 默认排序：时间倒序（日志/审计/时间线）、严重度优先（发现）；各面板折叠态记入 localStorage（键名沿用 `hiq.netdev*` 前缀）；
- 后台拉取指示复用现有 live 事件流样式，不新增转圈覆盖层。

### 10.9 设置三级导航与表单契约（R1 骨架，R2 起填充）

**现状问题**：设置 → 运维的第三级交互全是弹框——表单复杂度被弹框尺寸锁死，配置只能横向堆在四个二级页签里；v2 的新配置（五种 kind 注册、通知通道、事件接收、CVE feed、时序保留…）在弹框模型里无处安放。

**三级模型**：L1 设置 → L2 运维（现有四个二级页签保持）→ **L3 配置详情页**。点击 L2 的一个配置项（设备行、跳板行、通道行…），内容区以**由右向左的翻页动画**切换为 L3 表单页：左上角返回按钮 + 面包屑（`运维 / 设备与跳板 / core-sw-1`）。

动画与导航契约：

- L3 滑入 200ms、`cubic-bezier(0.2, 0, 0, 1)`，L2 内容同向轻视差（约 12px）强化层级感；返回时反向播放；
- `prefers-reduced-motion` 时退化为 150ms 淡入淡出；
- Esc = 返回；L3 内允许再进一层（设备 → SNMP 子表单），**深度上限 2**，动画同向叠加不弹框；
- L3 状态保持：返回再进不丢表单内容（未保存变更离开时提示）。

**弹框的存废**：表单类交互一律迁 L3（设备/跳板编辑迁入；TOFU 测试连接成为 L3 内联步骤）；**弹框仅保留阻塞确认类**（删除确认、紧急停止、危险提案二次确认）。判据一句话：表单进三级页，弹框只做确认。

**容量与扩展**：L2 只放「分组入口 + 每组一行状态摘要」，具体配置全部下沉 L3——新增配置增加的是 L3 页，不增加 L2 密度。v2 归位：kind 注册表单（R2）、通知通道 / 事件接收 / 时序保留（R3）、CVE feed / 案例偏好（R5）、红队门控（若附录 C 立项）。

**表单契约——选择题优先，填空题兜底**：

- 可枚举 → 选择题：下拉 / 分段控件 / 单选组（每个选项带一句说明文案），如厂商、kind、组策略、变更窗口、日志级别；
- 有限集合 → 复选组（协议勾选、通知事件分级）；
- 自由文本仅限不可枚举项：路径、地址、正则、ID——必带校验与 placeholder 示例；
- 数值 → 步进器 + 合理范围与单位；
- 每个配置项有默认值，推荐默认带徽标；用户改过的项标「已自定义」；
- 本契约适用于 v2 全部新表单与确认交互（含提案批准项、向导选项、设备卡动作面板），不只是设置页。

### C.1 门控（先于一切能力）

4. **生命周期**：engagement 到期自动回落；紧急停止覆盖红队动作；断线即停。

### D.3 回退语义与安全分类

- **后缀回退**（与 Claude Code/ZCode 的"按轮回退"对齐）：回退到事件 E 之前 =
  E 及之后所有事件触碰的每个文件还原到各自**动手前**的内容（文件原不存在则
  删除）。恢复前先写 `restore-keep` 反向事件（当前值留底）→ 回退本身可重做；
  **重做守卫**：反向事件之后一旦有新事件即禁用（防连坐）。
- **ZCode 式事前分类**：事件不可回退的唯一条件 = 后缀触碰了**活跃实体**
  （提案 executing/watching、作业 running/paused、割接 running/hold），
  分类随事件列表返回并在确认层列出实体名；执行时二次复检（预检竞态兜底）。
- **config.toml 专属警告**：整文件快照，回退会连带恢复 [netdev] 之外的同文件
  配置（如 bot 设置）在间隙内的改动——确认层固定警告。
- **绝不自动**：回退永远是人的点击；**绝不触碰设备**：UI 固定文案声明
  「仅恢复本地记录，设备回退请用提案/割接回滚」。

### D.4 编码模式对齐增量（同批落地）

1. **rewind 三分类**：`FileSnap` 增 `Hash`（快照前哈希）+ `PostHash`（写工具
   执行后经 `SetPostEditHook`/`SharedPostEditHook` 记录的"代理最后写入"哈希）；
   `Controller.RewindPreview(turn)` 按当前盘哈希分类
   safe（=PostHash）/ unsafe（≠PostHash，回退会丢外部修改）/ ignored（无哈希
   留痕的旧快照）；Message.tsx 确认层三档展示。
2. **Reapply**：`Rewind(code/both)` 先以 `Store.KeepCurrent` 把后缀各路径的
   当前值写成合成反向检查点（`rewind-keep` 前缀、边界取截断后的消息数），
   最新反向检查点在 rewind 菜单露出「重新应用上次回退」（对它做 code 恢复
   即重放；重放自身再留反向 → undo/redo 可持续翻转）。
3. checkpoint 包顺带修复：`Finalize()`（未结束事件的路径不再被 List 隐藏）、
   `NewWithLimit`、Begin/Finalize 后持续 prune、`DiffForTurn`/`restorePerm`
   改走 `safePath`（相对路径 + CWD≠root 的存量缺陷）。

### D.5 验收要点

- 建提案→批准→执行：状态历史出现三事件；回退到批准前提案回 draft；重做复原。
- 活跃割接/执行中提案：对应事件显示"不可回退（活跃实体）"，恢复调用被拒。
- 改 bot 设置后回退更早的 netdev 设置事件：确认层出现 config.toml 连带警告。
- 编码会话：外部手改被回退文件 → rewind 确认层列"会丢失外部修改"；
  回退后菜单出现「重新应用」，点按即复原。
