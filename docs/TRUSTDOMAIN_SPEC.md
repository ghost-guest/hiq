> **定位**: 定义 hiq 多机组网中**唯一立项的区块链能力**——私有网信任域（Trust Domain）账本，以及承载它的连接层管道。回答三个问题：
> ① 多台无公网 IP 的 hiq 主机如何组成一个私有网络（连接层，**不用链**）；

## 一、背景与动机

### 1.1 愿景与核心判断

产品方向：在每台服务器部署 hiq，形成可互相校验、互相委托的 AI 运维 fleet（AI 化运维，向 AGI 化演进）。

**核心判断：瓶颈不是模型智能，而是授权与问责**——"敢把多少执行权交给一个会幻觉的东西，事后能否说清楚它干了什么"。模型能力由厂商决定，hiq 能构筑的差异化是**敢放权的基础设施**：身份、授权、审计、协同。本 spec 定义其中的网络管道与信任面。

### 1.2 驱动场景（首发规模）

- 约 200 台机器使用 hiq，其中约 10 台为自有机器，需要组成一个私有网络；
- 这 10 台**均可访问公网（出站），但可能都没有公网 IP**（NAT/CGNAT 之后，无法被动入站连接）；
- 私网内主机需要互相验证身份、互验授权、全网可查健康状态，且**不依赖任何自有公网服务器作为信任锚**。

### 1.3 为什么是区块链（且只有这一处）

经完整排除法（附录 A）收敛：hiq 中绝大多数正当的"区块链"需求只需要密码学零件（签名、哈希链、透明日志）；**唯一必须使用链式结构的场景是"无中心可用的成员注册与撤销"**——隔离网或跨网络私网环境里，没有外部信任服务可用、不能选某台主机当 CA（单点失陷=信任面全灭）、多个对等方需要共享"谁有效"这一事实。

首发拓扑（跨网络、经不可信撮合点互联）比纯隔离局域网更适合账本的理由：**副本的网络多样性**——任何单一网络被攻陷，其余副本仍可证明完整历史；防篡改能力随拓扑分散增强。

### 1.4 设计不变量

本 spec 全文以下七条为硬约束，任何后续修订不得违反：

1. **链上只放控制面元数据**——凭证、哈希、公钥；任何原始内容（日志正文、消息、文件、业务数据）永不上链；
2. **无代币、无挖矿、无全局共识**——许可链，quorum 签名复制日志实现；女巫防护靠物理准入（管理员签名/扫码），不靠经济激励；
3. **信任面与撮合层解耦**——信令/中继 VPS 是不可信的连通性基础设施，不承载任何信任职能；
4. **撤销见即生效**——撤销记录一经出现（含未确认状态），任何主机立即拒绝被撤销方，宁误杀可恢复，不漏杀；
5. **全员验证**——每台成员主机持有账本完整副本并独立验证一切；验证逻辑自包含，**离线可验、永久可验**（不依赖外部时间源或在线服务）；
6. **低频控制面**——链上写频率必须显著低于检查点节奏；高频数据一律走链下加密信道；
7. **能力隔离胜过策略**——自主执行权限是结构性白名单（无执行路径），不是提示词约束（延续 NETDEV_SPEC v1 §6.1）。

## 二、范围与非目标

### 2.1 范围内（In Scope）

| 项 | 层 | 内容 |
|---|---|---|
| 连接层 | 无链 | hiq↔hiq 跨网互联：mDNS / IPv6 / STUN 打洞 / UPnP / TURN 中继优先级链 |
| 信任层 | 链 | 信任域账本：成员注册与撤销、能力令牌、审计互锚、自证摘要 |
| 治理 | 链 | 写入权限矩阵、管理员 quorum、紧急刹车、密钥轮换、终止记录 |
| 协作层接口 | 无链 | agent 委托执行的验证入口（账本查询能力），自主阶梯的扩权依据 |

### 2.2 非目标（Out of Scope，明确不做）

- **L3 overlay VPN**（虚拟 IP、任意 TCP 透明互通）——远期可选，首发只做应用层组网；
- 文档审批存证、合同流转、版本确权；
- 聊天消息上链或任何内容上链；
- 模型/API 用量结算、计费；
- Swarm 任务市场、跨组织算力交易与结算；
- 插件签名注册表（独立立项另行评估，见 §13.1 次近候选）；
- agent 成果存证（SLSA 式出处证明）独立立项——降级为审计哈希链的副产品；
- 公链接入、代币、跨链。

### 2.3 四问检验法（新增区块链提议的准入门槛）

任何未来"XX+链"提议，四问全过才立项，任一不过即用签名+数据库收工：

1. 参与方之间**真的互不信任**吗？（还是其实都认某个中心）
2. **找不到可接受的中立方**当仲裁者吗？（哪怕付费的）
3. 信任错配的**代价够高**吗？（高到值得支付性能/隐私/复杂度代价）
4. 能接受数据**公开（域内可见）、永久、低频**吗？

## 三、总体架构

三层各司其职，**链只出现在中间一层**：

```
┌─────────────────────────────────────────────────────────┐
│ 协作层（无链）  agent 委托 / 任务路由 / 自证公告板查询        │
│                 —— 兑现"用得上"                           │
├─────────────────────────────────────────────────────────┤
│ 信任层（链）    成员 / 撤销 / 令牌 / 审计锚 / 策略哈希        │
│                 许可链 = quorum 签名复制日志               │
│                 —— 解决"信得过"                           │
├─────────────────────────────────────────────────────────┤
│ 连接层（无链）  mDNS → IPv6 → STUN 打洞 → UPnP → TURN      │
│                 E2E 加密信道（复用 mobilebridge 栈）        │
│                 —— 解决"够得着"                           │
└─────────────────────────────────────────────────────────┘
```

账本"骑"在连接层管道上：账本 gossip 同步、检查点联签、委托消息全部走成员间 E2E 加密信道。链不参与连接的建立，它让连接建立之后的事情变得可信。

## 四、连接层设计（不用链）

### 4.1 连接建立优先级链

每一对 hiq 主机按以下顺序尝试，越靠前越快、越私密、越不依赖外部：

| 序 | 方式 | 依赖 | 说明 |
|---|---|---|---|
| ① | 同网段直连 | mDNS/DNS-SD | 零外网依赖，隔离网可用 |
| ② | IPv6 直连 | 双侧公网 IPv6 | **中国场景金矿**：大量无公网 IPv4 的机器有公网 IPv6；ICE 原生支持 v6 候选，常可免打洞直连 |
| ③ | IPv4 UDP 打洞 | 公共 STUN | 免费、无状态、不属于 hiq；锥形 NAT 有效（经验命中率 80–95% 的机器对可直连） |
| ④ | UPnP 端口映射 | 路由器开启 UPnP | 代码已有（`internal/mobilebridge/upnp.go`）；企业网常禁用，仅作增量 |
| ⑤ | TURN 中继兜底 | 自有 VPS | **唯一需要公网机器的环节**；只见密文（E2E 之下）；承载双侧对称 NAT/CGNAT 的少数机器对 |

ICE 按需建链：不是常驻满 mesh（10 台=45 对），谁要通信谁建链；账本同步走 gossip，不要求两两直连。

**传输 as-built（v0.7）**：Peer 传输先以 **TCP + mobilebridge 同款握手**落地（`internal/trustdomain/nettrans`：Ed25519 身份签名 + X25519 ECDH + HKDF + AES-256-GCM + 帧防重放，全部复用 `internal/mobilebridge`），覆盖局域网/直连地址（`bootstrap_peers`）。**信任面由链驱动**：握手双方各自从本地账本的成员注册表解析对方静态公钥，未准入/已撤销的连接即刻关闭且不披露原因。新成员经 `join <addr> <域ID>` 入域——域 ID（创世哈希）带外获取，是加入时的信任锚（等价 linkpeer QR 指纹比对），服务端 hello 签名对下载链做事后验证。WebRTC/NAT 穿透（②③⑤）作为另一种拨号方式后续叠加，Peer 接口不感知。

**平台注意**：发现机制在三个平台的支持度不同——Windows 原生 mDNS 发布受限，Linux 最小化服务器镜像常缺失 avahi-daemon（而服务器恰是 fleet 主力）。**发现回退链三平台统一**：mDNS → UDP 广播 → `bootstrap_peers` 手动配置（见 §15.1）；服务器场景默认走 `bootstrap_peers`。完整矩阵见 §十七。

**发现 as-built（v0.11）**：UDP 广播层落地（`nettrans/discovery.go`，零依赖三平台统一，mDNS 可后补为更优层级）——**信标（Beacon）**携带 域ID/成员ID/监听地址/时间戳/公钥/签名，接收方对照**自己账本**验证（同域、活跃成员、注册公钥一致、签名有效、±120s 新鲜）后才记忆该地址；发现只产出地址，信任仍由成员握手建立（发现不是信任，只是地址）。`run --discover`（或 `[trustdomain].discover`）启用：每 15s 广播信标 + 监听合并进对等集合，TTL 3 个周期；回环测试覆盖验证矩阵与跨域拒收。**quorum 棘轮（v0.11）**：`hiq trustdomain quorum <m>` 经 policy 记录升门槛——完整建域流程为 `init`（M=1 引导）→ `admit --admin` 各对端 → `quorum 3`；**只升不降**（失陷的单一管理员无法放松闸门），降门槛需人工重建域（终止+转生）。

### 4.2 撮合与兜底基础设施

- **撮合点**：现有 `cmd/linkpeer-signal`（knock-only WebSocket 信令，内存 TTL，不持久化）。只撮合、不被信任、只可见元数据——E2E 加密保证其无法解密内容、无法冒充成员；
- **兜底中继**：同一台或另一台廉价 VPS 跑 coturn。中继带宽为 KB/s 量级（控制面消息、账本同步、审计根），非媒体流；
- **多租户安全**：撮合/中继不可信 ⇒ 自有 10 台与客户 fleet 可共用同一套基础设施，信任域各自独立、互不可见；
- **单点退化**：VPS 失效时已建立的直连与信任域原样存活（去中心化红利），仅新增撮合暂时不可用；建议双引导（DNS 别名 + 备用地址硬编码）。

## 五、信任层：账本设计

### 5.1 账本记录类型（就这五类，多一类都不加）

| 记录 | 内容 | 解锁能力 |
|---|---|---|
| **成员（Member）** | 公钥 + 指纹 + 准入记录 + 角色 | 任意两台零配置建立已认证加密信道；新成员同步账本即获全局信任上下文 |
| **撤销（Revocation）** | 被除名成员指纹 + 时间 + 签名者 | 失陷主机秒级全网出局，无需轮换其他成员凭据 |
| **能力令牌（Token）** | "主体 A 可对资源 R 执行操作类 O，截止 T"（签发者签名） | 主机 B 机器可判地放行/拒绝委托请求（见 §七） |
| **审计锚（AuditAnchor）** | 各成员本地审计哈希链的链头（32 字节 Merkle 根） | 审计互锚：任何单一网络失陷后仍可证明审计史完整 |
| **自证摘要（Attestation）** | 版本 / 策略哈希 / 审计链头 / 健康结果 / 心跳时间 | 全网安全校验公告板：一条查询得全网状态 |

外加两类**治理记录**：策略变更（域规则修改，需 quorum + 公告期）、终止记录（见 §6.6）。

**身份与命名的原则（keys, not accounts）**：hiq 无登录/注册/用户名体系——这不是缺陷，是与本设计的对齐。成员记录可携带**自签的显示属性**（`display_name` / 备注 / 角色标签），名称是给人看的标签，可重复、可修改；**身份永远是指纹**。管理员密钥按**一人一钥**发放与保管——人类的身份同样以密钥承载（操作者归属见 §16-7），不引入任何账号/认证服务器体系。

### 5.2 记录与块的结构（示意）

```
Record {
  Type        enum      // member / revocation / token / audit_anchor / attestation / policy / terminal
  Subject     bytes     // 记录主体（成员指纹 / 令牌 ID / 锚定者）
  Payload     bytes     // 类型化载荷（只含元数据，不变量 #1）
  Issuer      PubKey    // 签发者
  Sig         []byte    // Issuer 对 (Type|Subject|Payload|PrevHash|Timestamp) 的签名
  Timestamp   uint64    // 辅助字段；排序权威来自链，不来自时钟（§5.4）
}

Block {
  Height      uint64
  PrevHash    [32]byte  // 链接——排序与删除可检测的来源
  Records     []Record
  Proposer    PubKey    // 轮值出块者（§5.5）
  ProposerSig []byte
  Checkpoint  *QuorumCheckpoint  // 周期性附加：m-of-n 管理员对当前链头的联签
}
```

### 5.3 链接（哈希链）买到的三样东西

1. **密码学排序**——成员语义是有序的（准入→撤销→再准入；令牌签发在撤销之前还是之后结论不同）。散装签名记录的时间戳可伪造可冲突；链把顺序变成哈希的一部分，重排即断链；
2. **删除可检测**——单条签名只证明"此记录存在过"；攻击者（含失陷管理员）整条删除撤销记录时剩余记录仍有效。链使**完整性**可验证：第 N+1 块存在即锚定第 N 块必须以该哈希存在，缺块可见。"删撤销记录让失陷主机复活"是最现实的攻击，链防的就是它；
3. **链头即全史摘要**——验证最新链头 + 检查点，即传递性背书全部历史。这是自证摘要里一个 32 字节"审计链头"能代表整个审计史的原因。

### 5.4 时钟与排序

块内 Timestamp 仅为展示辅助；**记录的权威顺序 = 链上位置**。跨主机时钟不要求同步；新鲜度判断（§6.4）使用检查点联签携带的共识时间。

### 5.5 共识与出块

- **出块**：成员按序号**轮流出块**，出块是义务不是权力——块内记录逐条验证签名与写入权限，不合法即被全网拒绝，坏块只损耗出块者自身信誉；
- **确认**：每 N 分钟（建议 10 分钟）由**管理员 quorum**（§6.2）对当前链头做检查点联签；
- **分叉裁决**：包含最新有效 quorum 检查点的链获胜；无检查点区间的短暂分叉按最长链临时接受，待下一检查点收敛；
- **写入频率**：按需出块（成员变更类）+ 自证摘要周期发布（建议每 60s，域内聚合后远低于块容量）；
- **规则版本化与升级**：创世记录携带验证规则版本（`rule_version`）；规则变更以策略记录写入，声明新版本与**生效高度**（activation height），生效前留公告期——成员软件按生效高度切换验证逻辑，避免升级期间链分裂。规则切换后仍运行旧版软件的成员将无法验证新块（可感知的强制升级信号）；
- **反滥用限制**：块大小上限（256KB）+ 单成员记录频率上限（自证摘要按限速节奏）；超限记录拒绝入块。出块者离线时按轮转序跳过，由下一位出块。

### 5.6 账本可见性（看到 ≠ 访问）

每台成员主机持有完整副本，本地可查：成员名单、状态板（自证摘要）、授权凭证（令牌）。**看不到**其他成员的文件、日志正文、会话与业务数据——访问需令牌授权 + 点对点加密信道。公告板告诉你 B 存在且健康，不等于让你读 B 的硬盘。

副本可见范围 = 全体成员可见的一切，因此"链上只放元数据"这条纪律同时就是隐私边界。

## 六、控制与治理

### 6.1 写入权限矩阵（角色化写入，链验证规则强制执行）

| 操作 | 谁能做 | 机制 |
|---|---|---|
| 发布自证摘要 | 每台成员，**只能签自己的** | 自己的密钥签名；冒充他人记录验证即拒 |
| 申请入域 | 任何主机（经 E2E 信道申请） | 管理员批准或物理扫码（带外准入） |
| 准入/撤销成员 | 管理员 quorum（5 取 3） | 联签记录，缺法定人数不生效 |
| 签发/吊销能力令牌 | 管理员或被授权签发者 | 签名 + 链上注册，到期自动失效 |
| 修改域策略/验证规则 | 管理员 quorum | 链上策略记录 + 公告期，全程留痕 |
| 验证账本 | **所有成员（强制）** | 验证规则内置于软件，不可豁免 |

设计原则：**日常运行零控制、关键动作强控制**——自证摘要等日常记录自主发布不需批准；只有改变权力结构的动作需要管理签名。

### 6.2 管理员 quorum 与容灾

- 管理权 m-of-n（建议 5 取 3）：单个管理员密钥丢失/被黑不影响域存续；
- **恢复密钥**：建域时预生成，离线保管（纸/USB），用于全体管理员密钥灾难性丢失时的域恢复；
- **密钥轮换**是链上记录：管理员换届、成员换钥匙均为可审计事件，没有"悄悄换锁"。

### 6.3 反向控制：连管理员也不能做什么

- **不能篡改历史**——哈希链 + 全员验证，改动全网立即可见；
- **不能冒充成员**——签名不可伪造，管理员也只能以管理员身份行动；
- **不能无痕操作**——准入、撤销、改规则，每个控制动作本身都是链上记录。

权力的天花板是链式结构买到的另一半控制："权力很大，但全程在玻璃房里行使"。这是敢对 agent 放权的信任根基——连管理员也改不动审计记录。

### 6.4 撤销与紧急刹车

- **撤销见即生效**（不变量 #4）：撤销记录一经出现——哪怕在未确认块中——任何主机立即拒绝被撤销方。误杀可通过恢复记录纠正，漏杀不可逆；
- **紧急刹车（PAUSE）**：管理员 quorum 可签发全局暂停记录，链上一出现，**全网所有 agent 立即从自动执行降级回只读诊断**（自主阶梯跌回 L1）。与撤销同一套传播机制，秒级生效。暂停不是终止——链必须存活，否则"解除暂停"无法可信传达。

### 6.5 成员退出与失陷处置

- 正常退出：撤销记录 + 本地副本注销，链继续运行（**成员退出 ≠ 链终止**）；
- 失陷处置：撤销 → 若需更高保障，令牌层全员重签发（令牌天然短周期，损失有界）。

### 6.6 终止（链必须能善终）

| 场景 | 动作 | 为什么必须显式终止 |
|---|---|---|
| **域解散**（fleet 退役） | quorum 签终止记录（链头哈希 + 关闭时间），账本归档 | 不终止的无主链可被复活——多年后旧管理密钥被盗可在废弃链上续写。规则：**终止记录之后的任何块一律无效** |
| **灾难转生**（全体管理密钥失陷） | 旧链签终止 → 新链 genesis，起点引用旧链头 | 彻底失陷无法原地修补，唯一正确动作是作废旧账开新账，同时保留审计连续性 |
| **冷归档**（合规留存） | 终结检查点 + 全员联签，离线封存 | 归档的链要**永远可离线验证**（不变量 #5），验证逻辑不得依赖外部时间源/在线服务 |

终止权与其他权力结构变更同级，归管理员 quorum。

## 七、能力令牌（授权设计）

### 7.1 动机

运维的最大软肋是长期凭据（SSH 私钥）撒得到处都是、撤不干净。能力令牌从结构上消灭该问题：**签名、限定范围、短周期、可撤销**——去中心化的最小权限原则。

### 7.2 令牌语义

```
CapabilityToken {
  Subject     成员指纹            // 谁被授权
  Resource    资源标识/资源类     // 对什么（资源以 ID/哈希引用，不含敏感细节）
  Operations  操作类白名单        // 可做什么（read / propose / execute-whitelisted …）
  ExpiresAt   截止时间            // 短周期（分钟~天级），到期自动失效
  Issuer      签发者公钥 + 签名
}
```

### 7.3 验证流程（毫秒级、离线可用）

**as-built（v0.8）**：`Delegation`（`internal/trustdomain/delegation.go`）承载签名的工作请求——令牌/主体/资源/操作/**载荷哈希绑定**/签发与截止时间，签名覆盖全部字段。验证五关全在执行端本地：新鲜度 → 身份（注册公钥 = 请求公钥 + 签名）→ 载荷绑定 → 令牌四态 → 范围（精确或 `*` 通配）。传输层（nettrans `WorkHandler`）在执行任何注册处理器之前先过此闸——处理器只见已验证的工作。时钟语义按 §16-3：执行端本地钟。

主机 B 收到 A 的委托请求：① 验 A 的信道签名（身份）→ ② 查本地账本副本：A 未被撤销、令牌存在且未过期、资源与操作匹配 → ③ 放行或拒绝。全程本地判断，不询问任何服务器。

### 7.4 与自主阶梯的关系

令牌是自主性的手柄。自主阶梯（承接 NETDEV 安全模型，此处仅作引用不在本 spec 展开）：

| 级 | 能力 | 令牌映射 |
|---|---|---|
| L1 | 只读诊断 | read 类令牌（netdev 现状） |
| L2 | 提案 + 人工签核 | propose 类令牌（proposal 流程现状） |
| L3 | 白名单内自动执行（幂等/可回滚/爆炸半径封顶） | execute-whitelisted 令牌，短周期签发 |
| L4 | 有界自主（信任半径随审计积累扩大） | 长周期令牌 + 审计互锚记录作为扩权依据 |
| L5 | fleet 交叉复核（提案由另一独立成员复核后自动执行） | 双签令牌（签发者 + 复核者） |

紧急刹车（§6.4）是任意时刻将全网拉回 L1 的手刹。

## 八、审计互锚与自证摘要

- **本地审计哈希链**（前置条件）：成员本地的审计记录（含 netdev 审计）先链成本地哈希链——普通日志防不了有权限者改记录，哈希链是"管理员也改不动历史"的最便宜手段；
- **互锚**：各成员周期性地把本地审计链头作为 AuditAnchor 记录写入域账本；跨网络副本多样性使任何单一网络失陷后审计史仍可证明完整（§1.3）；
- **公告板**：Attestation 记录聚合为全网状态视图——版本过旧/策略漂移/心跳超时/被撤销，任意成员一条查询即得。掉线检测是分布式的：自证摘要带新鲜度窗口，谁停止广播由全网各自独立发现，无需中心监控。

## 九、安全分析

### 9.1 威胁模型：防什么

| 攻击 | 防线 |
|---|---|
| 撮合/中继 VPS 被攻陷 | E2E 加密（握手签名 + AEAD）：只能见元数据、只能 DoS，不能解密不能冒充 |
| 失陷主机假冒他机 | 记录签名 + 写入权限矩阵：只能签自己的记录 |
| 失陷主机复活（撤销记录被删） | 哈希链删除可检测（§5.3-2）+ 撤销见即生效 |
| 管理员篡改历史/无痕操作 | 全员验证 + 玻璃房治理（§6.3） |
| 单管理员密钥丢失 | m-of-n quorum + 离线恢复密钥（§6.2） |
| 旧链复活攻击 | 终止记录终结规则（§6.6） |
| 单网络/机房失陷 | 副本网络多样性 + 审计互锚（§1.3、§八） |

### 9.2 威胁模型：不防什么（诚实边界）

- VPS 层 DoS（撮合不可用）——降级为直连存活 + 换 VPS；
- 恶意管理员**合法行使权力**造成的损害（链保证可追责，不保证不发生——权力在 quorum 手里）；
- 成员主机自身被完全攻陷后的本地数据泄露（链管信任，不管端安全——端安全靠 OS 密钥保管与既有 hiq 防线）；
- 分区期间的视图不一致（短暂分叉按检查点收敛，见 §5.5；高危操作要求近期检查点新鲜度）。

### 9.3 隐私与合规边界

- 链上记录仅含控制面元数据；凡有"被遗忘权"约束的个人信息（GDPR/PIPL）一律不上链——**不可删除性与删除权根本冲突**；
- 连哈希都需谨慎：可关联到个人的哈希（如 `hash(用户名+设备)`）仍可能被认定为个人信息，需加盐或只锚定聚合根；
- 元数据可见性：域内成员彼此可见身份/状态/授权关系——自有 fleet 可接受，此为可见性设计边界（§5.6）。

### 9.4 密钥安全

- 成员密钥复用现有分级保管（`internal/secret/store.go`：Windows DPAPI / macOS Keychain / Linux 桌面 Secret Service / 无头机 passphrase 派生，降级模式经 SecurityMode 显式暴露——完整分级见 §十七）；
- 链上身份密钥的赌注高于配对密钥（丢失=成员身份失效、泄露=可被冒充至撤销生效），故：密钥轮换为链上一等记录；恢复密钥离线预生成。

## 十、性能与容量估算

| 项 | 估算 | 依据 |
|---|---|---|
| 账本写入频率 | 个位数笔/秒封顶（千级成员域） | 成员变更低频；自证摘要 60s/成员；审计锚 10min/成员 |
| 账本存储 | **MB~GB 级/年**（10 台域：MB 级） | 控制面记录 ~100B/笔；最坏全网锚定约 10GB/年（万级成员），那是验证者的负担，成员跑轻副本 |
| 验证开销 | 冷启动全链验证秒级；增量验证常态 | 链头 + 检查点传递性背书（§5.3-3） |
| 连接建立 | 直连毫秒~秒级；经中继 +100ms 级延迟 | ICE 常规表现 |
| 中继带宽 | KB/s 量级/机器对 | 控制面消息，非媒体流 |
| 撤销生效 | 秒级（gossip 传播时间） | 撤销见即生效 |

**轻客户端原则**：桌面/普通成员节点不跑全量验证者，验证自身所需子集 + 检查点。全量副本是账本健壮性的来源（不变量 #5），不是每台节点的义务。

## 十一、实施路线图

### Phase 0 — MVP 管道验证（约两周）

1. 一台 VPS：现有 `linkpeer-signal` + coturn 各一份；

### Phase 1 — 信任域账本最小闭环

- `internal/trustdomain` 包：记录/块结构、签名验证、gossip 同步、轮转出块；

- 令牌签发/验证/过期/吊销；令牌注册上链；

- 本地审计哈希链（对接 `internal/netdev/audit.go`）；互锚记录；全网状态查询命令；PAUSE 记录与 agent 降级联动。

### Phase 4（远期，另立 spec）

- L3 overlay（内嵌 WireGuard，按需）；跨域联邦（域间锚定链头）；L4/L5 自主阶梯扩权。

## 十二、决策记录：为什么只有这一个区块链场景

**做**：私有网信任域账本（本 spec 全部内容）。许可链形态，无代币无挖矿，quorum 签名复制日志实现。

**不做**（完整清单及理由见附录 A）：文档审批存证、合同流转、版本确权、聊天上链、用量结算、Swarm 任务市场、L3 组网的链包装、成果存证独立立项、公链接入。

**必须的其实分两半**：签名身份、签名授权（令牌）、本地哈希链审计——这三样是纯密码学，不需要链；**唯一必须链式结构的是"无中心可用的成员注册与撤销"**。做完前三样，hiq 的信任问题解决 90%；第四样是本 spec 的主体。

**对外表述**：我们在唯一非链不可的地方用了链，其余全部拒绝——这是工程判断，不是功能列表装饰。

## 十三、重评触发条件（"目前"的边界）

以下**市场信号**（非技术冲动）出现前，§2.2 非目标答案不变；出现后重新评估：

1. 客户 fleet 之间需要**联邦互通**（跨组织信任传递，无主注册表成为真需求）；
2. 插件生态向**第三方开放发布**且 hiq 不愿当唯一签名方（供应链透明日志需求升级）；
3. 真实出现**跨组织的任务/算力交易市场**（无主结算成为刚需）；
4. 合规方要求**第三方可验证**的审计（对外锚定需求）。

### 13.1 次近候选（按距离排序——信号到达即可立项）

| 候选 | 还差什么信号 | 形态 |
|---|---|---|
| 插件签名 + 透明日志 | 「向第三方开放发布」或「以供应链防篡改为安全卖点对外承诺」，二选一的决策 | 签名部分必须（纯密码学）；透明日志为链形态（CT 式） |
| 运维报告对客户公证（netdev MSP 场景：服务商管理客户 fleet，客户要求验明"服务商声称做过的事"） | 客户/监管方提出"第三方可验证"的明确诉求 | 审计锚导出 + 客户侧轻客户端验证（不要求客户跑节点） |
| 跨组织威胁情报优先权证明（多个 netdev 用户共享 IOC/发现，"谁先报告"需要不可否认的排序） | 客户间情报共享社区真实形成，且不接受厂商当注册中心 | 哈希化提交 + 链上排序（排序恰是链的本职）；选择性披露保护提交者 |
| 自主 agent 间托管结算（远期：陌生方的 agent 互相购买任务/算力，需无中立方的履约保障） | 跨组织任务市场成型（触发条件 ③）且 agent 自主性到达 L4+ | 智能合约托管；链唯一不可替代的形态，但产品距离最远 |

前两者均**不改变本 spec 范围**：复用 §五 的账本机制，只新增记录类型与导出格式——先建信任域不会为它们浪费任何工作。

### 13.2 既有账本的零成本延伸（as-built v0.13，不新增立项）

以下功能由已承诺的账本机制直接生长出来，**不需要任何新链能力**：

1. **令牌委托链（as-built）**：持有者可转授子令牌——账本结构化强制四规则：**深度限 1**、**范围子集**（操作∈父集、资源不放宽）、**寿命更短**（到期早于父、发放时父未过期）、**只有持有者可转授**；`CheckToken` 沿委托链回溯——**撤销授予者即杀死全部下级授权**。CLI：`trustdomain delegate`；
2. **失联继任（as-built）**：policy 记录配置"管理员静默 N 秒 → 指定成员可晋升"；继任记录**无需 quorum**（这正是其意义）。确定性设计：超时判定用**记录自身签名时间戳 − 链内导出的最后管理员活动时间戳**——同一链的每个验证者结论一致，不依赖本地钟；晋升本身刷新管理员时钟。CLI：`succession <小时> <成员>...` 配置（quorum）、`promote` 触发；
3. **检查点即时间公证**：域内检查点自带共识时间戳，任何哈希经检查点锚定即获得"何时存在"的域内证明——自证摘要与审计锚已在隐式使用它。
竞态 | 撤销记录尚在未确认块时，其他主机已拒绝被撤销方（撤销见即生效） |

### 14.3 Phase 2/3 验收

- **令牌四态**：过期拒绝、吊销拒绝、资源/操作不匹配拒绝、正常放行，各设用例；
- **审计互锚**：本地审计链篡改一条记录后，互锚验证失败并能定位到链头不符；
- **紧急刹车**：PAUSE 记录出现后，在途自动执行在下一个检查点前降级回 L1；
- **回归**：与 linkpeer 手机配对、netdev 提案流程行为无变化。

### 15.2 进程入口（as-built：CLI 先行，boot 装配后移）

账本核心、节点服务、持久化已落地（`internal/trustdomain`）。当前入口为 CLI：

```
hiq trustdomain init     # 生成本机身份密钥 + 创世块（单管理员 quorum=1 引导域）
hiq trustdomain identity # 打印本机 ID + 公钥（交给管理员准入）
hiq trustdomain join     # <成员地址> <域ID>：拉取并验证全链后入域（域ID 带外锚定）
hiq trustdomain status   # 链头/成员/令牌/检查点/公告板
hiq trustdomain attest   # 自证摘要上链
hiq trustdomain admit    # 准入成员（读公钥文件；需管理员 quorum）
hiq trustdomain revoke   # 撤销成员（ID 前缀；见即生效）
hiq trustdomain token    # 签发能力令牌
hiq trustdomain exec      # 凭令牌发起委托工作：<地址> <令牌ID> <资源> <操作> <载荷JSON>
hiq trustdomain sync      # 一次性对等同步（脚本友好；exec 前拉取新签发的令牌块）
hiq trustdomain run       # 节点守护：--listen + --bootstrap + tick；--executor netdev 挂只读诊断执行器
```

**Agent 工具（v0.10）**：`netdev_fleet`（本地公告板：成员/自证/暂停态，只读不出网）与 `netdev_remote`（跨机委托：agent 只表达意图，工具自动选择覆盖 (资源,操作) 的令牌——精确优先于通配；无覆盖令牌即拒并提示补签命令；PAUSE 态拒）。仅在 `[trustdomain] enabled` 时注册，未入域主机对 agent 不可见。**PAUSE as-built（§6.4）**：quorum 签名记录，生效即停全部委托验证（含只读——刹车从严，本地诊断不受影响），Resume 记录解除；`VerifyDelegation` 返回 `ErrDomainPaused`。**热重载（§16-9 缓解）**：节点 Tick 检测账本文件 mtime/size 变化并重载验证，同域且不低于本地高度才采纳——CLI 与守护共享数据目录的单写者冲突在实践中解除（控制端口仍为长期项）。

**首个真实消费者（v0.9）**：netdev 的只读诊断接入委托执行（`internal/netdev/remotepeer.go`）——资源词汇表 `netdev/health`（健康面板）/`netdev/triage`（主机体检电池），仅 `read` 操作可表达，经既有 guardrails/审计管线执行。双进程冒烟：成员 B 凭令牌跨机拉取 A 的 HealthSnapshot，越权操作本地即拒。

单管理员引导域（M=1）上 admit/revoke/token 可离线完成；多管理员域经网络联署（`run` 的对等节点提供联署服务）。**boot 装配推迟**：Controller 侧尚无信任域消费者（委托验证入口随传输层落地），此时在 `internal/boot` 构造实例是无消费者的死代码——传输层合入时一并接入（届时 `enabled && domain_id != ""` 才构造）。双进程全链路（init→admit→join→attest→跨机同步）已冒烟验证。

## 十六、未决问题

1. 管理员的 linkpeer 手机端可否作为 quorum 成员（手机端密钥保管等级是否足够）？
2. TURN REST 凭据的轮换节奏是否与域账本联动？
3. 令牌 `ExpiresAt` 的判定时钟：本地钟 + 安全裕度，还是检查点共识时间？（倾向前者 + 裕度，待定）
4. 多域并存（一台 hiq 加入多个域）的 UI 与账本隔离边界；
5. 账本备份/恢复的标准格式——离线封存包应包含：全链 + 全部检查点签名 + 验证规则版本元数据；
6. 成员动态变化期间出块轮转序的稳定性定义（避免频繁跳变）；
7. **操作者归属**：人在成员主机上发起的动作（如提案签核）是否需与操作者密钥**共同签名**，以实现审计归属到"人"的粒度（多管理员 fleet 的追责前提；与问题 1 手机端作为操作者密钥载体天然联动）；
8. 若需要商业授权分级，采用**签名 license 文件**（离线可验）而非账号体系——与不变量 #3 一致；
9. **本地单写者**：`run` 守护与一次性 CLI 共享同一数据目录时账本分叉（守护持有内存链，CLI 追加磁盘链，守护不自动重载——冒烟实测）。短期约定：变更（admit/token/revoke）先于守护启动；长期方案：`run` 暴露本地环回控制端口，CLI 优先经守护执行变更。

## 十七、平台适配矩阵（Windows / macOS / Linux）

spec 主体天然跨平台（Go + pion WebRTC + 标准网络协议，无 CGO 依赖）。真正的平台工作量集中在**发现、密钥保管、常驻形态、防火墙**四件事：

| 关注点 | Windows | macOS | Linux | 适配措施 |
|---|---|---|---|---|
| 局域网发现 | 原生 mDNS 发布受限（需 DNSSD/Bonjour 兼容处理） | 原生最佳（Bonjour 同源） | 桌面依赖 avahi-daemon；**最小化服务器镜像常缺失** | 发现回退链三平台统一：mDNS → UDP 广播 → `bootstrap_peers`；服务器默认 `bootstrap_peers` |
| 密钥保管 | DPAPI（现有） | Keychain（现有） | 桌面 Secret Service（现有）/ 无头 passphrase（现有）；降级模式经 SecurityMode 暴露 | 链身份密钥要求 ≥ passphrase 级；运行在降级模式时 UI 必须明示；恢复密钥离线保管兜底（§6.2） |
| 防火墙首跑 | Defender 首次监听 UDP 弹窗/规则 | 应用防火墙提示 | ufw/firewalld 需手工放行 | 打洞为出站发起不受阻；同网直连监听端口需入站规则——部署文档按平台列明放行项 |
| 常驻形态 | 桌面（tray，现有）/ 服务 | launchd；**注意 App Nap 会节流后台定时器**（60s 自证可能被推迟到分钟级） | systemd 单元（服务器主力形态） | 无头守护复用现有 `internal/serve` HTTP 前端 + boot 装配；交付 systemd 单元模板；macOS 以 launchd agent 运行规避 App Nap |
| 时钟偏斜 | 少见 | 少见 | 服务器/VM 常见 | 令牌判定本地钟 + 安全裕度（§16-3）；自证新鲜度用检查点共识时间（§5.4） |
| WebRTC / UPnP / 纯 Go 运行时 | ✅ | ✅ | ✅ | 无需适配 |

### 17.1 最薄弱环节判定

**Linux 无头服务器是三平台中适配风险最高的形态**——密钥保管退到 passphrase 级、发现依赖 `bootstrap_peers`、时钟偏斜概率最高——而它恰恰是 fleet 愿景的主力部署形态。因此：Phase 0 的验收用例（§14.1）必须在 Linux 无头环境跑一遍，不能只在开发机（Windows/macOS）上验证。

### 17.2 平台工作清单（进入路线图）

1. 发现回退链实现（mDNS 库选型 → UDP 广播 → bootstrap_peers），三平台各验一次（Phase 0）；
2. systemd 单元模板 + 无头部署文档（Phase 0/1）；
3. macOS 常驻的 App Nap 规避验证（launchd agent 或进程级断言）（Phase 1）；
4. 防火墙放行文档（按平台列明端口与协议）（Phase 1）；
5. 降级 SecurityMode 下的 UI 明示与链身份密钥准入检查（Phase 2，配合令牌）。

| agent 成果存证（SLSA 式） | 用的就是审计哈希链，是审计层副产品，不单独立项 |
| fleet 共享状态的链包装 | 多节点锁/变更窗口是真需求，但是普通分布式系统工程（租约+复制日志），不该用链招牌 |
| 聊天消息上链 | 延迟/隐私/撤回/容量四项全输；连 Status/Session 等 Web3 聊天也不把消息上链（消息走 P2P 加密路由，链只管身份） |
| 公链/代币 | 女巫防护靠物理准入已足够；代币引入的是共识负担与监管负担，无对应收益 |

## 附录 B：术语表

| 术语 | 定义 |
|---|---|
| 信任域（Trust Domain） | 一组互验身份的 hiq 成员及其共享账本；域是信任的边界 |
| 许可链 | 成员经准许方可参与的一类链；本 spec 中等价于 quorum 签名复制日志 |
| 能力令牌 | 签名的限时范围授权凭证，取代长期凭据 |
| 审计锚 | 成员本地审计哈希链头写入域账本的记录 |
| 自证摘要 | 成员周期性发布的自身状态签名摘要（版本/策略哈希/审计链头/健康） |
| 检查点 | 管理员 quorum 对链头的联签，用于分叉裁决与传递性背书 |
| 终止记录 | 使链不可再延长的治理记录；用于解散、转生、归档 |
| 紧急刹车（PAUSE） | 使全网 agent 立即降级回只读的全局暂停记录 |
| 撮合点 | 不可信的连接建立辅助服务（linkpeer-signal），只传递候选信息 |
